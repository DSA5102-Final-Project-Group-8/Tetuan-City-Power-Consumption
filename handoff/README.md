# Handoff data for teammates

All files are produced by the Task 1 / Task 2 / Task 3 cells of `DSA5102_Final_Project_Group8.ipynb`
(re-running the notebook rewrites them). The final notebook itself only needs `data/`.

| File | Content | Used by |
|---|---|---|
| `daily_load_72d.csv` | 364 days × 72 columns: hourly mean demand `zone_1_h00` … `zone_3_h23` (mean of six 10-minute readings) | Task 2 (PCA/KPCA), Task 3 (K-means, GMM) |
| `daily_metadata.csv` | Daily mean weather, `weekday` (0 = Monday), `split` (development / holdout); join on `date` | Tasks 2–3 |
| `task1_predictions_holdout.csv.gz` | Test-period (2017-10-19 – 2017-12-30) predictions of every Task 1 model: B0, R1, R2, R3 (Ridge), RF, GB, HYB | Section 6 integrated analysis |
| `task1_predictions_oof.csv.gz` | Validation-fold predictions (2017-06-01 – 2017-10-18) of the same models with their selected settings | Section 6 |
| `task1_metrics.csv` | Mean CV and test RMSE / MAE / R² for every model and zone | Report tables |
| `task2_pca_scores.csv` | Date-indexed scores from the PCA scale and dimension selected by development-period validation | Task 3 and Section 6 |
| `task2_kpca_scores.csv` | Date-indexed scores from the selected RBF Kernel PCA configuration | Task 3 sensitivity analysis |
| `task2_reconstruction_metrics.csv` | Validation and holdout reconstruction RMSE for raw PCA, standardized PCA and RBF Kernel PCA | Task 2 results and Section 6 |
| `task3_kmeans_input_72d_standardized.csv` | 364 × 72 standardised clustering input (scaler fitted on development days only) | Task 3: GMM fits on the identical matrix |
| `task3_kmeans_labels.csv` | Daily K-means labels (k = 3, full-year descriptive fit), regime names and split | Task 3 comparison, Section 6 |
| `task3_kmeans_labels_devfit.csv` | Development-only K-means labels (holdout-protocol sensitivity check) | Section 6 |
| `task3_kmeans_centroids.csv` | 3 × 72 regime centroids in original kW units | Task 3 interpretation |
| `task3_kmeans_zone_means.csv` | Mean daily load of each regime by zone | Task 3 interpretation |
| `task3_kmeans_metrics.csv` | k = 2 … 10 model-selection metrics (inertia, silhouette, Davies-Bouldin) | Task 3 model selection |

Prediction files: key `(timestamp, zone, model)`, a `date` column (YYYY-MM-DD) for joining to
daily clusters, `residual = y_true - y_pred` (observed minus predicted). Primary models:
`R3` (linear) and `RF` (nonlinear). `pd.read_csv` reads the `.gz` files directly.

Protocol: development period 2017-01-01 – 2017-10-18 for all model choices, final test period
2017-10-19 – 2017-12-30. For claims about unseen days, fit scalers / PCA / clustering on
development dates only.


## FengZhengqi: GMM and integrated analysis

The following are regenerated by Sections 5.2, 5.3.2 and 6.2. They are optional
experiment handoffs, never required inputs to the final notebook.

| File | Content |
|---|---|
| `task3_gmm_selection.csv` | Development-only BIC/AIC search, convergence and minimum cluster sizes; selected configuration is five components with tied covariance |
| `task3_gmm_labels.csv` | Date, full-year descriptive component, separately ordered development-fit component, full-year maximum posterior probability, split, and five full-year posterior probabilities |
| `task3_gmm_comparison.csv` | K-means, selected five-component GMM and three-component GMM on identical 72-dimensional input; silhouette, DB and ARI |
| `task3_regime_prediction_errors.csv` | R3/RF RMSE, MAE, mean residual, day/observation counts by zone, split and regime, with explicit retrospective or development-fit scope |

Full-year GMM components are ordered by observed mean load: G0 is low-demand
autumn, G1 regular, G2 September-October transition, G3 late May-June, and G4
summer peak. Development-fit IDs have a separate order and different meanings.
Posterior probabilities apply only to the full-year model. Labels based on
realised daily demand are diagnostic and are not advance predictions of day type.
